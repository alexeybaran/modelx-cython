# Native specialization contracts

The compiler keeps the exported Space/Cell structure. A proved native path and
object-capable Cython implement the same logical Cell and cache. A Python-callable
method generated by Cython is still compiled code; it is not a second modelx
interpreter. Internal cache/formula functions preserve the public method and
virtual override path. There is no execution Frame or prepared-policy input ABI.

## Proof and scope

Types come from representative tracing, explicit type declarations and static
use analysis. Tracing must cover the model's relevant type alternatives; it is
not a mathematical proof about every possible future input. Observed integers
outside signed 64 bits use objects. Arrays use native views only for a consistent
supported native-endian buffer format; other formats remain objects.

Formula-local facts do not cross nested functions, classes, lambdas or
comprehension scopes. A statement-changing lowering declines observable binding
effects it cannot preserve, including globals, nonlocals and exception targets.
Declining an optimization retains ordinary Cython execution.

Exact receiver checks preserve subclass dispatch. Read-only enum definitions
permit constants on an exact receiver; subclasses still read their actual
Reference. Enum values use the underlying integer representation, not an
overridable conversion method. Private formula admission uses native signatures,
binding and override safety, not formula length.

Integer arithmetic specialization proves bounds for every intermediate. The
emitted input guards and binary64 exact-integer bound determine safety; operation
counts do not. Outside the guards, the original boxed arithmetic remains.
Native math recognizes callable capabilities and checks the current callable's
identity at runtime, so Reference aliases and replacements retain behavior.

## Helper providers

A Python function Reference can declare `__modelx_cython_helper__` as
`(provider, operation)`. The packaged provider supplies `.pyx` and `.pxd`
resources. Its Cython entry receives the current Python callable first and must
delegate when callable identity, types or data layout are unsupported.

The single `helpers.CAPABILITIES` registry defines optional capability metadata:

| Metadata suffix | Meaning / shape |
|---|---|
| `reduction` | `f64_sum`, `bool_any`, `bool_all` or `f64_max` |
| `numeric` | Numeric-return operation identifier |
| `clamped`, `clamped_context` | Clamped lookup operation identifiers |
| `optional` | Guarded membership/value operation identifier |
| `grouped` | Two operation identifiers; optionally a third context probe |
| `bounded`, `bound_bounded` | Bounded lookup operation identifiers |
| `bound_grouped`, `bound_numeric` | Exactly three operation identifiers |

Suffixes expand to `__modelx_cython_<suffix>__`. Names and tuple arities are
validated while tracing. The registry is shared by runtime metadata and merged
References; providers do not need insurance-specific compiler branches.

Numeric contexts implement the common `LookupContext` ABI. They cache prepared
input resources and indices, never policy results or formula execution state.
Prepared resources must be disposable: normal model pickling retains Cell
caches, while a context reconstructs empty and prepares resources on demand.
Resources held by contexts must keep their owners alive. Separate compiled
packages must not confuse their private native resource types.

Exclusive lookup reuse is enabled only on confined collection receivers whose
References remain stable. Ordinary public receivers retain checked/synchronized
resource access. Compiler recognition of optional grouped/clamped sequences is
conservative; equivalent unsupported sequences keep their ordinary helper calls.
Generalizing such recognition must not skip binding effects or reorder calls.

## Generators

Registered reductions can lower to ordinary Cython loops when their iterator,
primitive value types, bindings and fallback are proved. Numeric sums support
typed range/singleton bindings and typed filters. Mixed int64/float comparisons
that could lose integer precision are not newly admitted. Unknown filters,
arbitrary iterators and unsafe captures keep their generator path.

Generated variables avoid authored names. A prefix appearing in a formula is
not itself a reason to reject it. Fallbacks preserve the current helper callable,
lazy generator behavior, exceptions and lexical bindings. No general formula or
pandas interpreter is involved.

## Storage and collection

Dense and primary-table ceilings are common memory policies: 65,536 dense
entries and 4,096 private primary entries. They do not limit legal key domains.
Physical dense windows keep the original logical domain and exact spill. The
primary table keeps its half-full policy and grows through overflow storage.
Low-level allocation additionally checks addressable byte size independently
of the compiler's budget.

Native numeric stores preserve published entries when pickled, including exact
result bits; failed reservations remain retryable. Readiness uses normal `bint`
arrays and standard Cython serialization.

The generated build script detects Cython releases whose structural array-type
equality ignores inner dimensions. On affected releases it corrects that
build-time equality before Cython allocates serialization temporaries. Assignment
compatibility, native layouts and the ordinary runtime serializer are unchanged.
This prevents undersized or incorrectly strided buffers when restoring different
multidimensional cache shapes. It is a dependency repair, not a new serializer.

Receiver reuse requires the semantic independence/confinement/stable-Reference
contract. Fresh receivers are the automatic default when reuse is not declared.
Unsupported export-runtime adapters retain the normal collection path. Successful
private scalar chunks may merge in completion order, with ordinary floating
roundoff; failures are propagated in original domain order. Existing public
Cell calls, collection APIs and caller scheduling remain the execution boundary.

There is no native PGO training or profile-use build. Timing profiles guide
development, while the existing small model trace supplies types and working-set
observations. Diagnostic switches remain available for ablation and compatibility;
the adjusted model benchmarks require no per-Cell performance settings.
